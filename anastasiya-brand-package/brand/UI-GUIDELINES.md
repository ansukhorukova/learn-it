# UI Guidelines

## Priority
Function first. Brand second. Decoration third.

## Screen hierarchy
Every screen should have:
1. one clear purpose
2. one obvious primary action
3. a limited number of visual emphasis points

## Buttons
Primary:
- pink fill
- use for the single most important action in a region
- no permanent large glow

Secondary:
- dark surface
- subtle border
- pink border only when useful

Destructive:
- use semantic red, not brand pink

## Cards
Cards are not the default layout primitive.
Use spacing and section hierarchy first.

Create a card only when content benefits from a visual boundary.

## Forms
- always show labels
- group related fields
- show validation close to the field
- use pink focus ring
- errors are red and explicit
- success is green and explicit

## Tables
- dark restrained headers
- strong readability
- zebra striping only if necessary
- selected row may use subtle brand tint
- avoid neon borders per row

## Empty states
Good empty states are calm and useful.

Pattern:
- short description
- one next action
- optional small visual

Example:
"No experiments yet. Create one to start collecting results."

## Loading
Prefer skeletons for content.
Use spinners only for short, bounded actions.

## Notifications
Success = green
Warning = amber
Error = red
Info = blue
Brand pink is not a semantic status.

## Charts
Use brand pink for the primary series.
Use purple only as secondary.
Use semantic colors only when they mean something.
Avoid rainbow palettes.
